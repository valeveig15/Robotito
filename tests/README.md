# Generative and combinatorial verification for Robotito

These test modules supplement (not replace) the existing Node, browser and historical suites. `npm test` runs deterministic checks and `npm run test:ci` adds browser coverage. GitHub Actions runs the CI command for PRs into `main` and on `main` updates.

| Command | Responsibility |
|---|---|
| `npm run test:kit` | PRNG, complete pair/critical-triple covering arrays, reproducibility and failure replay |
| `npm run test:regressions` | Versioned historical cases in `tests/regressions/semantic-issues.json` |
| `npm run test:properties:matrix` | Three seeds of generative/property tests across language, context, audio, time, weather, voice and emotions |
| `npm run test:browser:matrix` | Three Playwright seeds for viewport, language, avatar, mood and audio-state interactions, plus persistence on reload |
| `npm run test:ci` | All new and previous test suites |

**Reproduce a specific property failure:**

```bash
ROBOTITO_TEST_SEED=17 ROBOTITO_REPLAY_PROPERTY='property-name' ROBOTITO_REPLAY_CASE=42 npm run test:properties
```

Failures report seed, index, original input and a reduced case when a shrinker exists. Shrinkers are read lazily (at most 64 candidates), and the smallest failing candidate is retained instead of allowing a later larger case to replace it. To add a permanent regression, first add a unique issue ID, failing input, expected result and why it was wrong to `tests/regressions/semantic-issues.json`; fix the behavior and keep the case in CI.

Historical issue fixtures can also assert individual fields of every action in a compound request using `expectedActions` (including nested paths such as `entities.exerciseNumber`). This prevents a correct top-level intent from concealing an unauthorized first action.

The Chromium scenario matrix also crosses offline/online operation, tab suspension, class/mute audio gates and responsive viewports. A separate browser check sets the microphone permission state to denied and verifies that no recording starts; on headless runners with no audio devices, the capture attempt may report `NotFoundError` rather than `NotAllowedError`. Both reject the stream, but this does **not** substitute for a real microphone permission-denial test on physical hardware. The offline scenarios write, read and delete local IndexedDB records. They are **simulated network and permission conditions**, not measurements from actual phones or microphones.

**P03: comparación por tipo de micrófono (sin identificadores personales).** Los manifiestos de clips y sesiones pueden incluir `deviceClass` con uno de estos valores: `phone`, `tablet`, `built-in`, `headset`, `usb`, `recorder`, `other` o `unspecified`. Si se omite, se clasifica como `unspecified`; nunca se infiere un tipo a partir del navegador, ni se recopilan IDs o números de serie. El reporte JSON añade `byDevice` y `deviceMetrics` para clips, y `continuousEvaluation.byDevice` para sesiones continuas. **No se debe afirmar precisión por dispositivo cuando la muestra es pequeña o no existe**. Comparar tasas con horas negativas realmente observadas, y no sumar clases con contextos no representativos. Los ejemplos de manifiesto son plantillas: reemplazar rutas, etiquetas, derechos de uso y metadatos por datos autorizados; si se usa `open-license`, indicar además `license` y `source` reales a nivel del manifiesto.

**P03 — etiquetas y supresión coherentes:** `audio-annotation-integrity.js` comprueba que los sonidos humanos anotados no se superpongan en el tiempo con segmentos que nunca deben enviarse al clasificador. Si se solapan, el editor avisa y no acepta la marca; `loadManifest` y `evaluateContinuous` fallan cerrados también cuando se los llama directamente, sin pasar por el editor. Las fronteras exactamente contiguas son legales. La prueba `audio-annotation-integrity-regression` y casos en regresiones de manifiesto, línea de tiempo y Chromium cubren ambas direcciones. No se analizan audios reales de personas.

**P03 — cancelación segura del laboratorio local:** la grabación no continúa ni genera archivos si el consentimiento se revoca, el navegador suspende la pestaña, el micrófono termina o el usuario cancela una solicitud de permiso todavía pendiente. Las operaciones asíncronas de `getUserMedia`, `MediaRecorder` y `decodeAudioData` mantienen una generación de sesión: resultados tardíos se descartan después de cancelaciones, cambios de archivo o salida de página. Chromium comprueba revocación en marcha, permiso tardío, descartar durante decodificación y visibilidad de la página. Se usan pistas de micrófono simuladas, no participantes reales.

**P03 — laboratorio local para grabar y etiquetar sonido:** `tools/audio-corpus-studio.html` es una herramienta separada de la app principal: carga un archivo existente o graba con `MediaRecorder` tras consentimiento y clic explícitos, permite registrar eventos humanos e intervalos suprimidos y descarga un audio y su JSON con idéntica ruta base. No sube muestras ni instala YAMNet. `npm run test:audio:studio` abre la página real en Chromium, usa un WAV sintético y el micrófono falso del navegador, descarga ambos archivos, valida el manifiesto con `loadManifest` y ejecuta `validate:audio` con los bytes descargados. No se han probado micrófonos físicos ni sonidos de personas.

**P03 — preflight de grabaciones sin cargar modelo:** `npm run validate:audio -- /ruta/manifest.json` abre los archivos autorizados en Chromium local, verifica la decodificación real y comprueba que cada anotación o supresión esté dentro de los segundos existentes de audio. No descarga ni ejecuta YAMNet. `evaluate:audio` ejecuta el mismo control **antes** de cualquier inferencia, sin guardar resultados parciales si un archivo falla. Las pruebas de integración contienen un WAV sintético, una muestra corrupta y un intervalo fuera de la duración; no se recopilaron sonidos humanos ni datos de micrófono físico.

**P03 — estimación conservadora por fuente:** `sourceGroupMetrics` y `sourceGroupMetricsBySplit` evitan que extraer 10 clips del mismo archivo original se convierta en 10 ensayos estadísticamente independientes. Se cuenta un grupo negativo una única vez, y un grupo que contiene la etiqueta positiva de interés no se cuenta como negativo. Cada especie humana tiene `negativeSourceGroups`, `falsePositiveSourceGroups`, tasa e intervalo superior Wilson 95 %; ambos son `null` sin grupos negativos declarados. Se conservan los números históricos **por clip**, pero no se deben interpretar como evidencia de muestras independientes. La hipótesis de independencia entre grupos también necesita auditoría externa; las regresiones y los datos sintéticos nunca aprueban automáticamente reacciones humanas.

**P03 — particiones independientes declaradas:** los manifiestos pueden llevar `sourceGroup` (ID seudónimo de grabación/sesión original) y `evaluationSplit` (`development`, `validation` o `test`). Es obligatorio declarar un grupo para asignar partición. La comprobación **rechaza** que dos clips/segmentos asociados a la misma fuente aparezcan en particiones distintas, incluso cuando sus bytes sean diferentes. Múltiples fragmentos de una misma fuente **sí** pueden compartir grupo dentro de una única partición, pero siguen siendo observaciones correlacionadas. Los informes muestran `splitMetrics` de clips, `continuousEvaluation.bySplit` y únicamente **cantidades** de grupos y archivos por partición en `datasetIntegrity`; nunca publican los IDs de grupo. Las grabaciones sin etiquetas permanecen en `unspecified` y `ungroupedRecordings`: no se presume independencia. El control depende de etiquetas suministradas por la persona y `independentlyVerified` permanece `false`; no reemplaza inspeccionar los originales ni comprobar separaciones entre participantes y sesiones, y nunca habilita automáticamente reacciones humanas.

**P03 — protección contra duplicados de grabaciones:** antes de enviar audio al clasificador, `audio-evaluation-manifest.js` calcula SHA-256 localmente en fragmentos de 64 KiB y rechaza archivos con bytes idénticos, incluso con distintos ID, nombres o enlaces y entre clips y sesiones continuas. El informe solo declara la cantidad de fuentes únicas y la comprobación realizada; no publica huellas digitales de grabaciones, datos de micrófono ni rutas locales. Un audio recortado, convertido o editado puede escapar de la comparación exacta; hay que auditar también la independencia por persona, evento, grabación original y partición de validación. La prueba sintética de CI no sustituye datos reales.

P03 also accepts annotated continuous sessions in the optional `evaluate:audio` manifest. Actual locally decoded audio is classified by the genuine YAMNet Worker, then the **offline reference event counter** reports episodes per observed negative hour, excluding suppression and missing time. It does not run Robotito's actual avatar reactions. See `tests/fixtures/audio-timeline-manifest.example.json`; no recordings are shipped or automatically downloaded.

The P03 evaluation now keeps **time-ordered 0.975s window scores**; two adjacent same-class windows are required to mark a human sound in a multi-window clip, and mixed-human or isolated spikes abstain. Single short clips remain evaluable. This prevents combining non-simultaneous maximum class scores into a fictional classification and does not enable reactions or certify accuracy.

The P03 real-sound evaluator is separate from synthetic CI. A licence-aware ESC-50 local manifest generator (`npm run prepare:audio:esc50 -- /path/to/ESC-50 1`) selects cough, sneeze, laugh, baby crying, clapping plus noise/impact negatives from a **separately obtained** CC BY-NC dataset. No audio is committed or automatically downloaded; only noncommercial uses permitted by the dataset licence apply. The original ESC-50 clip labels are weak and the output cannot approve automatic reactions. 

The P03 real-sound evaluator is separate from synthetic CI: `npm run evaluate:audio -- /ruta/manifest.json` processes only a locally labelled and authorized corpus through the actual YAMNet Worker (not a simulated classifier). It now handles events shorter than the 0.975s YAMNet window by symmetric silence padding and always includes the last section of each recording. It produces a per-clip confusion matrix with precision/recall and false-positive *clips* per negative recording hour, disaggregated by sound source, plus Wilson 95% error-rate bounds; these figures are **not continuous-listening false alarms per hour**; **never** auto-enables human-event reactions or presents synthetic reports as calibration.

Coverage targets are the explicitly declared pairwise and critical triple relationships, **not** the entire Cartesian product. The property matrix certifies 785 targets per seed. Each browser matrix certifies 441 targets and exercises real Chromium handlers at simulated screen sizes, not physical devices. Hardware-dependent camera, microphone, voice and real-device accessibility need separate validation.

A desktop overflow defect found by the new test was traced to `layout-resizer.js` computing grid tracks without subtracting container padding. The correction and overflow assertion remain as regression coverage.
